# 会话透镜 · Session Lens

一个可安装的本地 Codex 插件，包含 stdio MCP、可视面板、独立 loopback 预览和简短协作 skill。Python 3.10+，无第三方运行依赖。监测无需 API Key；可选外置大脑需要自行配置外部服务。

## 体验

```sh
python3 server.py --http
```

打开命令输出的 dashboardUrl。面板读取本机最近会话；每五秒刷新数据，首轮扫描后增量读取。项目筛选读取 Codex 已保存的项目名与会话归属，同目录的不同项目按 ID 区分；临时目录聊天归入“未归属项目”。数量仅包含最近最多 40 个主会话样本。数据不可见时显示未知，不用演示数据填补。手动切换“演示场景”可以体验不同状态。

## 安装

此包的上级目录含 `.agents/plugins/marketplace.json`，将完整上级目录作为本地 marketplace：

```sh
codex plugin marketplace add /absolute/path/to/codex-session-helper
codex plugin add session-lens@session-lens-local
```

在新聊天里调用“会话透镜”，或说“打开会话透镜”。如现有聊天没有加载新增工具，重新打开聊天或重启桌面 App；不要为了加载插件中断正在执行的工作。

MCP UI 使用 `text/html;profile=mcp-app` 和标准宿主桥接。宿主能否呈现本地插件 UI 需要实际支持；独立面板使用同一份 HTML 和真实数据，不依赖内嵌 UI。

## 能力与限制

### 自动续接

选中已完成、已停止或失败的会话，点击“自动续接”。插件先提取有界的原对话摘录和 Git 状态，保存到仓库外的续接包；准备本地材料本身不调用模型。

- 在支持 MCP Apps 的内嵌面板中，请求通过宿主消息交给 Codex，由 AI 生成真实交接摘要，再按插件 skill 创建新聊天继续。界面中的“已交给 Codex”不代表新聊天已经创建，最终以聊天中的执行结果和链接为准。
- 独立网页提供官方 `codex://new` 草稿链接。打开后仍需在 Codex 按一次发送，AI 才会生成摘要并在该新聊天继续。官方链接不能自动发送消息。
- AI 总结、子 agent 和新聊天会正常消耗模型 token；后台采样仍不调用模型。原任务已完成时不得编造新的开发工作。
- 活动或状态未知的源会话不能自动续接；本插件不会停止它。摘录可能被筛选或截断，AI 需要核实关键事实并保留不确定性。

- 多工作区的最近会话、当前输入用量、协作分工、易读活动记录、历史错误与重试记录。
- 活动名称由本地规则识别明确的工具与命令类别，连续同类记录合并；已返回不代表测试通过。技术标识保留在折叠详情中。
- 子 agent 分工由主聊天通过 session_describe_agent 明确提供；没有说明时显示通用任务名称，不根据路径猜职责。
- 续接导出包含可观察状态和 Git 元数据，存于 `~/.codex/artifacts/<project-name>/session-helper/`；不代表完整业务摘要或代码备份。
- 原始会话和数据库只读；格式变化或历史不可读时降级为信息不足。遵循 CODEX_HOME 查找会话数据。
- 面板是读取时采样；没有新事件不能证明模型没在工作。无实时通知/自动压缩/请求接管能力。
- 正常刷新不调用模型。复杂诊断和语义总结由用户主动触发，面板不会后台定时启动推理任务。
- 独立预览只监听 127.0.0.1，入口令牌换取 HttpOnly 本地 cookie。监测不上传会话数据；主动启用外置分析时，所选材料会发送给配置的服务。

## 解析卡顿任务 → DP 规划 → Codex 执行

选中会话旁的“解析卡顿任务”是针对已有任务的完整流程：

1. **本地解析和标记**：读取有界的可读原对话、监测状态与 Git 元数据，提取原目标、最新要求，列出容量等待、上下文占用、未返回工具或无新事件等疑似线索。此步骤不调用模型，也不会仅凭无新事件判定卡死。
2. **主动请求 DeepSeek 规划**：需要设置中允许“子任务分发”。按一次调用发送必要材料，输出目标、判断的完成项、剩余事项、不确定性、任务类型（分析 / 代码 / 验证）、依赖与建议文件范围。DP 只规划；这些结论均待 Codex 核验。
3. **准备 Codex 执行包**：审阅并选择包含必要依赖的任务。源会话或旧子任务仍在活动时先停止旧执行；新对话改变约束或完成项时重新解析。单纯停止事件不强迫重复模型规划。文件范围未知或重叠的写任务分波串行，容量等待时最多一个，其他情况最多两个。
4. **Codex 实际执行与回报**：独立面板打开官方 Codex 草稿后需按发送；内嵌面板将请求交给 Codex。Codex 先领取执行包、核实原目录与 AGENTS.md，再按依赖派出真正的子 agent，处理代码和验证，回写真实 agent 标识、结果与证据。主协调者核验后形成整体验证报告。UI 消息已提交、DP 计划或执行包已准备均不代表执行成功。

每次派发使用小上下文：目标、必要约束、文件归属、上游短结论和验收条件。主协调者只回收简短结果，完整材料和报告留在仓库外。拆分有助于隔离长上下文与独立工作，但不能保证缓解服务限流、容量不足或耗时工具。

任务标记为待排查、DP规划待审阅、已规划、待原任务结束、待分发、执行中、待汇总、已汇总或受阻。再次打开优先恢复旧记录和进度，不覆盖标记、重复规划或重新派发。文件位于 `~/.codex/artifacts/codex-session-helper/rescues/`。执行包和源任务都有原子领取记录，防止重复点击或不同协调聊天重复写同一源任务；源状态未知时不自动接管或重发。

若 Codex 宿主没有多 agent 工具，应明确报告并保留计划，不用纯分析调用冒充代码执行。本插件没有自动停止桌面活跃请求的接口；源任务有未返回工具时，还需核实旧进程与已生效操作。DP规划和Codex执行按各自服务计费；本地解析、标记、恢复和进度查询不调用模型。

## 外置大脑子任务分发

在“外置大脑设置”里单独勾选“子任务分发”，再进入外置大脑的第四个选项。现有配置不会自动开启此功能。

1. 填写总目标和最少的共享材料，默认不附原对话。
2. 编辑本地模板或手动添加任务；也可点击“AI 拆分清单”，消耗一次请求生成 1–6 项独立的分析任务，生成后不会自动执行。
3. 审查任务要求、勾选需要的项，选择逐项或最多 2 项同时分析，再点击“分发选中子任务”。
4. 查看逐项进度、结果、用量、缓存命中和失败原因。各项结束后在本地合并结果，交给 Codex 核验；合并与轮询不调用模型。

各项都是当前已配置外部模型的独立分析请求，共享材料会重复发送，因此子任务会分别计费；每项沿用输入字符和输出 token 上限，面板显示选中任务的预算。拆分请求、子任务用量分别显示，缓存命中记录的是原请求用量。失败请求可能在服务端产生费用但没有返回 usage，以服务账单为准。失败不会自动重试，模型设置中途改变后也不继续发出后续任务。

“停止后续任务”影响尚未分派的项，已经交给分析器或服务的请求继续等待，仍可能计费。关闭窗口只停止该窗口轮询。任务组 JSON 保存在 `~/.codex/artifacts/codex-session-helper/external-brain/dispatches/`，可用任务组 ID 在刷新后恢复查看；服务重启导致源请求状态未知时明确标为中断，不自动重发。

这些子任务分析调用方提供的材料，没有本地文件、终端或代码修改权限。任务应互相独立，有前后依赖的工作由主 Codex 分阶段安排。主聊天可通过 `external_brain_plan`、`external_brain_dispatch`、`external_brain_dispatch_status` 与 `external_brain_dispatch_stop` 使用同一功能；主聊天只收短结论，完整清单、材料和结果留在面板与本地文件。

## 跨应用接续

顶部常驻紫色“外置大脑”主入口；会话操作区有同色“外置大脑 · AI 分析”。旁边“接续到其他聊天 / 应用”支持选择目标，外置模型已经生成交接摘要时也提供同样的选择。

| 目标 | 本地入口做到哪一步 | 用户后续操作 |
| --- | --- | --- |
| Codex | 保留草稿与内嵌宿主续接 | 草稿按发送；宿主创建结果以实际聊天链接为准 |
| Cursor | 使用官方 prompt deeplink 预填指令，不自动执行 | 先打开原项目、按需新建聊天，再检查并发送 |
| Claude / Claude Code | 提供通用指令、Markdown 附件和安全引用的 CLI 启动命令 | Claude Code 在终端运行复制的命令；桌面/网页 Claude 上传附件并发送 |
| Trae | 提供通用指令和 Markdown 附件 | 打开原项目、新建聊天，粘贴指令；无法读取仓库外文件时手动附加 |

交接文件包含有界原对话摘录、Git 元数据和已有的语义摘要（若已生成），保存到 `~/.codex/artifacts/codex-session-helper/transfers/<packageId>.md`，权限 `0600`。准备材料本身不生成 AI 摘要；只有已有摘要的交接才标记为待核验摘要。导出、复制和切换应用不再次调用模型，用户在目标应用发送或启动 Claude Code 后按该应用规则计费。

插件不迁移其他应用的内部会话数据库，也不接管仍在运行的请求。目标助手需核验源任务已停止、工作目录、AGENTS.md、分支及未提交改动，再继续已有授权内的明确待办。Claude 桌面/网页版能否操作本机仓库取决于其已配置的能力；无法直接读本机路径时使用附件。

Cursor 官方草稿链接：https://cursor.com/docs/reference/deeplinks ；Claude Code 交互启动命令：https://code.claude.com/docs/en/cli-reference 。未为 Trae 或 Claude 桌面版臆造自动发送协议。

## 可选外置大脑

点击面板顶部“外置大脑设置”，填写 DeepSeek 服务地址、模型与 API Key，保存后可以测试连接。默认关闭，默认服务为 `https://api.deepseek.com`，模型为 `deepseek-flash`。兼容服务可配置根地址（例如含 `/v1`）；需要支持 Chat Completions 的 JSON 输出格式。Key 只在本地网页密码框输入，不要发到聊天或工具参数中。

三个场景可以分别启用：

- **通用分析**：Codex 通过 `external_brain_analyze` 分派问题，或在面板输入问题。默认只发送问题与手动提供的材料。
- **进展解释**：解释所选会话的监测状态、活动与分工，默认不发送原对话。
- **交接摘要**：对已结束会话的有界原对话摘录与机械状态生成摘要，标记“待 Codex 核验”，再提供续接入口。不能恢复正在执行的请求。

前两种场景可以主动勾选“附带原对话”。外部结果仅作分析建议，主 Codex 核实后执行原授权范围内的工作。此功能通过插件工具接入，不替换主 Codex 模型。默认需要主动请求；可另行开启“允许 Codex 自主委派”。面板刷新与本地任务查询不调用模型。

默认每次输入上限 24,000 字符、输出上限 2,048 token，默认关闭 DeepSeek thinking；这些是本地预算设置，不是费用保证。连接测试也会发起一次小额外部请求。同一服务进程中的重复任务合并，成功结果缓存 10 分钟，缓存命中显示原请求用量且不重复调用；不同服务进程同时提交仍可能分别计费。请求失败不自动重试，避免隐式重复计费。

配置、结果与缓存位于 `~/.codex/artifacts/codex-session-helper/external-brain/`。Key 单独存为 `private/api-key.json`，文件权限 `0600`，目录权限 `0700`，使用本地文件保存而非系统钥匙串；也可通过 `DEEPSEEK_API_KEY` 环境变量提供，已有本地 Key 优先。接口只返回是否已配置，不返回 Key；已知服务 Key 会从发送材料与结果中隐藏，这不等于通用敏感信息扫描。请只选必要材料。

未填写自己的 Key 前，测试仅能验证本地逻辑与模拟服务，不能代表已连接真实 DeepSeek。

macOS 的 HTTPS 调用使用自带 `/usr/bin/curl`，读取系统证书信任与适用的 HTTP/HTTPS 代理，保持证书校验开启；Key 通过标准输入传递，不出现在进程命令参数中。连接上限 10 秒，整个请求上限 90 秒；仍不自动重试。其他平台使用 Python 标准库 HTTPS。证书、认证、连接和超时分别报错。

## 停止与卸载

前台预览按 Ctrl-C 停止。由插件启动的预览 PID 在 `~/.codex/artifacts/codex-session-helper/runtime.json`，核对进程后可结束它。

```sh
codex plugin remove session-lens@session-lens-local
```

插件卸载不删除已导出的续接材料。
